# 智能引用（smart-quote）

接管麦麦的引用回复行为：**引用与否由本插件按配置判定**，不再依赖模型给出的参数。

> ⚠️ **使用前注意**：本插件接管的是 Maisaka 决策链上的 `reply` 工具调用。启用后
> `set_quote` / `attach_at` 不再下发给模型，由插件在响应后写入最终值，因此模型无法自行决定引用。

## 为什么需要它

麦麦内置的 `reply` 工具带一个 `set_quote` 参数，**默认值是 `True`**——只要全局开关开着，
模型默认就会引用回复：

```
effective_set_quote = 模型传的 set_quote（默认 True） AND 全局 enable_reply_quote
```

想要"平时不引用、只在合适的时候引用"，靠麦麦自带配置做不到：全局的 `enable_reply_quote`
是**总闸**，关掉就一律不引用，无法按会话类型、按消息新旧细分。

本插件在这条决策链上插了一层**策略层**，由插件自行判定引用与否：

- `before_request` 把 `set_quote` 与 `attach_at` 从下发给模型的 `reply` 工具 schema 里
  **移除**——模型看不到这两个参数，也就不会去填，不白耗 token；
- `after_response` 按策略**无条件写入**最终值（`set_quote` 必写，需要 @ 时再补 `attach_at`）。

好处是不存在「模型省略参数 → `bool(None)` 被当成 `False`」这类歧义分支；
即使模型因看过旧快照而仍传了 `set_quote`，也会被覆盖，不影响结果。

> 麦麦里还有两处引用来源**不受本插件控制**：
>
> 1. `chat.reply_style.enable_reply_quote` 是**总闸**
>    （`effective_set_quote = set_quote AND enable_reply_quote`），**必须保持 `true`**，
>    否则本插件写入的 `set_quote=True` 会被抹掉，插件将彻底无法引用；
> 2. `chinese_typo.enable_correction_quote`：机器人打错字后补发纠正消息时，麦麦会让
>    纠正的那条自动引用上一条。这一步发生在 `reply` 工具内部的发送流水线里，
>    插件阶段拿不到，无法干预。若不希望出现这种引用，可在麦麦配置里关掉该功能。

## 功能

- **间隔条件**：可设定「被回复的消息间隔多少条以上」才引用——回复较早的消息时引用才有意义，
  紧邻消息不引用。判定依据是从本次上下文中按顺序解析出的消息索引差，与实际群聊体验一致。
- **软硬双阈值**：`min_message_gap` 是**软**条件（达到即引用，未达到交给随机判定）；
  `no_quote_below_gap` 是**硬**否决（不足即不引用，不参与随机）。
- **关键词条目（可选·可加多条）**：按**被回复消息的正文**决定引不引用。每条给出
  「关键词 + 命中后怎么做 + 在哪些会话生效」，像一份可增删的清单——在面板上点「添加」
  新增一条，逐条填即可。条目**自上而下匹配，命中第一条即采用其结论、不再往下看
  （顺序即优先级）**，所以把「不引用」的条目排在前面，就等价于"黑名单优先"。
  匹配方式是子串包含、忽略大小写，不写正则也不分词；每条还能单独限定
  「不限 / 仅群聊 / 仅私聊」，甚至限定到具体群号 / QQ 号。**默认留空，不影响使用。**
- **群聊 / 私聊分别配置**：两类会话各有独立的启用开关、固定引用行为、间隔阈值、名单与
  **各自的随机权重**，互不干扰——每个会话节都完整自包含，改群聊绝不会连带影响私聊。
  私聊默认**不 @**（一对一说话，@ 没有意义）。
- **随机权重**：该节所有条件均无结论时，于「引用 / 不引用 / @」中按权重选择；`@` 与另两项
  **叠加而非三选一**（先随机二态，再独立随机一次是否 @）。权重为相对值，无需归一化，
  在 WebUI 中以滑条调节。**没有全局权重**。
- **可 @ 对方**：通过麦麦原生的 `attach_at` 参数实现真 @（会提醒对方），@ 组件由麦麦在
  自己流程内拼接，**不破坏分段回复与文本润色**。
- **可隐藏富回复参数**：把 `attach_pic` / `attach_emoji` 从 `reply` 工具的 schema 中移除——
  模型看不到就不会去用，不白耗 token。回复阶段另有兜底剥离。
- **生效名单 / 排除名单**：可按群号或用户号精细控制，排除名单优先。
- **配置面板**：每个配置项均带说明；可选值直接给**下拉框**，无需记忆取值写法。
- **两个查询命令**：`/引用状态` 查看当前会话的策略与判定结果，`/引用关键词` 逐条打印
  关键词条目与两类会话的策略概览。

## 安装

1. 把插件目录放入麦麦主程序的 `plugins` 目录（目录名随意，插件靠 `_manifest.json` 识别；
   本仓库克隆下来是 `maibot-smart-quote`）
2. 重启麦麦，或在 WebUI 插件中心安装
3. 在 WebUI → 插件管理 → **智能引用** → 启用插件
4. 按需调整群聊 / 私聊策略

插件为标准 SDK 插件（`maibot-plugin-sdk`，由麦麦 Runner 内置提供），**无第三方依赖**，
无需手动安装任何包。

## 工作原理

通过麦麦公开的两个 Hook 扩展点实现：

| Hook | 作用 |
|---|---|
| `maisaka.planner.before_request` | **记录 + 移除**。记录本次上下文中的消息顺序（按 `session_id` 缓存 msg_id 列表）供间隔计算；从 `reply` 工具参数中移除本插件接管的参数（附图 / 表情 / `set_quote` / `attach_at`）；顺带沉淀会话类型 |
| `maisaka.planner.after_response` | **改写**。按策略把 `reply` 调用的 `set_quote` / `attach_at` 改成目标形态，并兜底剥掉模型自带的附图参数 |

> ⚠️ **返回值形态**：两个 Hook 都是阻塞型，必须返回
> `{"action": "continue", "modified_kwargs": {…原始载荷的全部键…, <被改动的键>}}`。
> Runner 只认 `modified_kwargs` 这一个键，宿主用它**整体替换** kwargs（不是逐键合并）；
> 返回裸字典（如直接 `{"output_items": [...]}`）会被静默丢弃，且不产生任何警告日志。

完整链路：

```
Planner 构造请求体（items：Context Item 快照）
 → maisaka.planner.before_request（本插件）
     → 解析 <message msg_id="..."> 标签，缓存消息顺序表与每条消息的正文（按 session_id）
     → 从 tool_definitions 里移除 reply 的 attach_pic / attach_emoji / set_quote / attach_at
     → 返回 {"action":"continue","modified_kwargs":{items, tool_definitions, …}}（未改动时返回 None）
 → 请求发给模型
 → 模型产出 FunctionCallItem（func_name="reply"）
 → maisaka.planner.after_response（本插件，可写）
     → 按下方「判定规则」得出结论
     → 无条件写入 tool_call.args["set_quote"]，需要 @ 时再补 ["attach_at"]
     → 返回 {"action":"continue","modified_kwargs":{output_items, item_schema_version, …}}（未改动时返回 None）
 → 麦麦采纳改写后的参数，真正执行 reply
```

插件在模型产出之后、工具真正执行之前介入，因此改写会真正生效；工具裁剪发生在请求发出之前，
只影响模型"看得见什么"，两者互不干扰。

### 会话类型怎么判定

群聊与私聊走的是两套策略，因此每次判定都要先确认「这是哪类会话」。

麦麦的 `session_id` 是平台、路由与群号/用户号拼接后的 MD5 摘要，字符串里**不含** `group`
之类的字面量，无法靠关键词分辨。插件按以下顺序取值：

1. 本次上下文 `items` 里出现 `group_card="…"`——这是群聊消息独有的属性（麦麦用群名片填充），
   出现即可**确定**是群聊；
2. 载荷里的显式布尔字段（`is_group_chat` / `is_group`）或非空 `group_id`；
3. 本会话此前沉淀过的结论（`before_request` 写入的内存缓存）；
4. 宿主能力 `chat.get_all_streams` 返回的 `is_group_session`（**权威**，主进程执行）；
5. 当前进程内直接反查 `chat_manager`（仅兜底）；
6. 都拿不到 → 保守判为私聊。

> 第 4 步是主路径。插件 Runner 是**独立子进程**，进程内的 `chat_manager` 是另一份实例、
> 内存里没有任何会话，因此「在插件里直接 import `chat_manager`」并不可靠——必须走宿主能力。

正常运行时第 4 步即可给出结论，`/引用状态` 显示的会话类型与实际一致。

## 配置

插件加载后由 Runner 在插件目录生成 `config.toml`（**不随仓库分发**），可在 WebUI 修改。
**大部分参数在面板里点选即可**；关键词条目在面板上点「添加」逐条填最省事，
手写 `[[keywords.entries]]` 也行。

配置节只有 `[plugin]` `[group]` `[private]` `[keywords]` `[advanced]`——
**没有全局权重节**，权重就写在各自的会话节里。生成出来的文件形如：

```toml
[plugin]
enabled = true
config_version = "1.0.0"

[group]                      # 群聊策略（本节完整自包含）
enabled = true
default_quote = false
min_message_gap = 5
no_quote_below_gap = 1
whitelist = []
blacklist = []
random_enabled = true
quote_weight = 0.25
no_quote_weight = 0.75
at_weight = 0.3

[private]                    # 私聊策略（字段与 [group] 相同，仅默认值有差异）
enabled = true
default_quote = false
min_message_gap = 0
no_quote_below_gap = 0
whitelist = []
blacklist = []
random_enabled = false
quote_weight = 0.2
no_quote_weight = 0.8
at_weight = 0.0

[keywords]                   # 关键词条目（按被回复消息的正文匹配）
entries = []                 # 条目列表；留空 = 不启用

[advanced]
verbose_log = false
strip_rich_attachments = true
```

各字段含义见下表。

### 配置项一览

| 配置项 | 说明 |
|--------|------|
| `plugin.enabled` | 是否启用插件（默认开）。关闭后本插件不介入引用决策，行为回到麦麦原始逻辑 |
| `plugin.config_version` | 配置 **schema** 版本，请勿修改。它决定是否触发一次配置迁移/重写，与插件版本号无关 |
| `group.enabled` | 是否对群聊启用本节策略（默认开）。关闭后跳过本节的名单与间隔条件，改用随机判定 |
| `group.default_quote` | 群聊**固定引用行为**（默认不引用）。⚠ 仅在「启用随机判定」关闭时生效 |
| `group.min_message_gap` | 群聊**引用间隔阈值**（**软**条件）。间隔达到该值即引用，未达到则交给随机判定。`0` = 不启用 |
| `group.no_quote_below_gap` | 群聊**硬**阈值：间隔低于它一律不引用，**不参与随机**。`0` = 不启用。与上一项相互独立 |
| `group.whitelist` / `blacklist` | 群聊生效名单 / 排除名单，排除名单优先 |
| `group.random_enabled` | 群聊无结论时是否按权重随机（默认开）；关闭则采用 `group.default_quote` |
| `group.quote_weight` | 群聊命中「引用」的相对权重，**WebUI 滑条**（0~1，步长 0.05） |
| `group.no_quote_weight` | 群聊命中「不引用」的相对权重，**WebUI 滑条** |
| `group.at_weight` | 群聊 @ 对方的概率，**WebUI 滑条**。与另两项独立叠加；需麦麦开启富回复 |
| `private.*` | 私聊策略，字段含义与 `group.*` 完全相同。差异只在默认值：私聊 `min_message_gap` = `0`、`no_quote_below_gap` = `0`、`random_enabled` = `false`、`at_weight` = `0`（私聊默认一律不引用、也不 @） |
| `keywords.entries` | **关键词条目列表**（默认空 = 不启用）。在面板上点「添加」逐条配置；手写时用 `[[keywords.entries]]`。条目自上而下匹配、**命中第一条即停**（顺序即优先级） |
| `entries[].name` | 备注名，只用于日志与 `/引用关键词` 的输出，留空也可以 |
| `entries[].enabled` | 是否启用这一条（默认开）。关掉后该条被跳过，其余条目不受影响 |
| `entries[].keywords` | 该条的关键词。被回复的消息正文**包含其中任一**即算命中；子串匹配、忽略大小写、不写正则、不分词 |
| `entries[].action` | 命中后怎么做：`引用` / `不引用`（**面板为下拉框**） |
| `entries[].session_type` | 该条的生效会话：`不限` / `仅群聊` / `仅私聊`（**面板为下拉框**；旧值 `any` / `group` / `private` 仍兼容） |
| `entries[].sessions` | 该条的**限定名单**：只对这些群号 / QQ 号生效；留空 = 不限 |
| `advanced.verbose_log` | 输出每次判定的详细信息，排查问题时开启 |
| `advanced.strip_rich_attachments` | 把 `attach_pic` / `attach_emoji` 等富回复参数从下发给模型的 `reply` 工具中移除，让模型看不到 |

### 随机权重细则

某节的所有条件均无结论时，若该节的「启用随机判定」开着，就在「引用 / 不引用 / @」
三个形态中按权重选择。**`@` 与另两项叠加，不是三选一**：先随机「引用 / 不引用」，
再独立随机一次「是否 @」。所以调大 `at_weight` 只让 `@` 更常出现，
不影响引用与不引用之间的比例。

- 权重是**相对值**，无需归一化。群聊默认 `0.25 / 0.75 / @0.3` ≈ 引用 25%、不引用 75%，
  其中约 30% 会 @；私聊默认 `0.2 / 0.8 / @0`（关掉了随机判定，这套值只在开启后才生效）。
- 三项在 WebUI 里都是**滑条**，拖动即可（`0` 表示该形态永不出现）。
- 想要"必引用"就只填 `quote_weight`；`@` 要 0 就把它拉到 0。
- `@` 会贴在**句首**，渲染成 `@某人 正文`；多段回复时只加在第一段。

> 💡 **@ 形态的前置条件**：麦麦的 `experimental.enable_rich_reply` 必须为 `true`。
> 因为 `attach_at` 属于富回复参数，麦麦在未开启时会直接丢弃它；未开启时插件不会硬塞，
> 而是自动退化为普通回复（`/引用关键词` 会给出提示）。
> 开了富回复后模型会多出三个参数（`attach_pic` / `attach_emoji` / `attach_at`），
> 由同一个开关控制，插件无法只解锁其中一个——因此本插件在
> `strip_rich_attachments = true`（默认）时，会在请求发出前把这些参数从 `reply` 工具的
> schema 里直接删掉，只留下自己接管的 `attach_at`。

### 关键词条目（可选·可加多条）

仅当「群聊 / 私聊」两节表达不了需求时才需要用到它。**默认留空，留空完全不影响使用。**

它决定的是「**要不要引用被回复的那条消息**」：拿那条消息的**正文**去匹配关键词。
每条条目自己带三样东西：**关键词**、**命中后怎么做**、**在哪些会话生效**。
在面板上点「添加」新增一条，条目内逐项填写；每个字段都有备注与占位提示，照着填即可。

**条目自上而下匹配，命中第一条即采用其结论、不再往下看——顺序即优先级。**
所以把「不引用」的条目排在前面，就等价于"黑名单优先"（与「排除名单优先于生效名单」
是同一个思路：靠顺序表达优先级，而不是藏一条看不见的规则）。

匹配方式是**子串包含、忽略大小写**，不写正则、也不分词——填什么就按字面找什么。

#### 字段一览

| 字段 | 默认值 | 面板上的标签 | 说明 |
|------|--------|--------------|------|
| `name` | `""` | 备注名 | 只用于日志与 `/引用关键词` 的输出，留空也可以 |
| `enabled` | `true` | 启用 | 关掉后这一条被跳过，其余条目不受影响 |
| `keywords` | `[]` | 关键词 | 被回复的消息包含其中任一关键词 → 命中；留空 = 这条永不命中 |
| `action` | `"引用"` | 命中后 | `引用` / `不引用`（**面板为下拉框**） |
| `session_type` | `"不限"` | 生效会话 | `不限` / `仅群聊` / `仅私聊`（**面板为下拉框**；旧值 `any` / `group` / `private` 仍兼容） |
| `sessions` | `[]` | 限定群号 / QQ 号 | 只对这些群 / 人生效；留空 = 不限 |

**三条要点：**

- **匹配的是「被回复的那条消息」**，不是当前这句话。判定「要不要引用它」时，看它自己的内容。
- **顺序即优先级。** 想"黑名单优先"，就把「不引用」的条目往上拖；反过来也一样成立。
- **取不到正文时按未命中处理。** 目标消息过旧、不在本次上下文里时无法匹配，此时这一条
  不参与判定，继续走后面的名单与间隔条件——与间隔条件同样保守：宁可放过，不误判。

> 命中任一条关键词条目后，下面的通用策略（`[group]` / `[private]`）就不再参与判定。

## 判定规则

对每一次 `reply` 调用，按以下顺序判定，**得到第一个明确结论即停止**：

1. **关键词条目** — 拿被回复消息的正文，按条目顺序自上而下匹配；命中某条即采用该条的
   `action`（`引用` / `不引用`）。取不到正文、或没有条目适用/命中则跳过本步
2. **该会话类型未启用会话控制** — 落到随机判定（未启用随机判定时用该会话类型的 `default_quote`）
3. **排除名单命中** — 一律不引用；生效名单非空且不在其中 → 落到随机判定
4. **间隔条件**（`min_message_gap > 0` 或 `no_quote_below_gap > 0` 时参与判定）
   - `间隔 < no_quote_below_gap` → **硬性否决**，一律不引用，**不参与随机**
   - `间隔 < min_message_gap` → 落到**随机判定**（回复的是很新的消息，引用意义不大）
   - `间隔 ≥ min_message_gap` → **一律引用**
5. **两个阈值均未启用、或目标不在上下文** → 该条件不参与判定，落到随机判定

> **优先级**：关键词条目 > 硬阈值 > 间隔条件 > 随机判定。
> 随机判定只在"前面的条件均无明确结论"时才接手。

> ⚠️ 两个阈值语义不同，勿混用：
> - `min_message_gap` 是**软**条件——"间隔达到才算命中"，未达到则交给随机判定；
> - `no_quote_below_gap` 是**硬**否决——"间隔不足即不引用"，直接结束判定。
>
> 另外「条件未启用」**不等于**「条件命中」：`min_message_gap = 0` 时该条件完全不参与判定，
> 不会强制引用。

### 三种回复形态

上面的判定与关键词条目最终都会落到这三种形态之一：

| 形态 | 实际发出的参数 | 效果 |
|------|----------------|------|
| **引用** | `set_quote=True` | 引用回复 |
| **不引用** | `set_quote=False` | 普通回复 |
| **@对方** | `set_quote=False` + `attach_at=[目标 msg_id]` | @ 目标消息的发送者后回复（真 @，会提醒） |

> `@对方` 需要麦麦 `experimental.enable_rich_reply = true`；未开启时插件会自动退化为
> 「不引用」，不会发出一条无效的 @。

## 命令

| 命令 | 别名 | 说明 |
|------|------|------|
| `/引用状态` | `/引用查询` | 查看当前会话的类型、生效策略、关键词条目、本节的随机权重与缓存消息数 |
| `/引用关键词` | `/引用配置` | 逐条打印关键词条目（顺序 / 备注名 / 关键词 / 命中后 / 生效会话）与群聊 / 私聊策略概览 |

## 常见配置示例

**场景一：平时不引用，只回复旧消息时引用**

```toml
[group]
enabled = true
min_message_gap = 5      # 引用间隔阈值：隔 5 条以上才引用
no_quote_below_gap = 3   # 低于 3 条一律不引用（可选，见场景四）
```

> 群聊里「隔 5 条以上 → 一律引用」，紧邻的消息交给随机判定（默认约 20% 引用）。
> 想让紧邻的消息也绝不引用，就把 `no_quote_below_gap` 一起用上。

**场景二：私聊完全不要引用**

```toml
[private]
random_enabled = false   # 关掉随机判定
default_quote = false    # 固定不引用 → 私聊一律不引用
min_message_gap = 0      # 间隔条件不参与
```

> ⚠️ 只把 `[private].default_quote` 设为 `false` **不够**：那个值是「固定引用行为」，
> 仅在「启用随机判定」关闭时生效；而随机判定默认开着，条件又都用不上，于是会落到随机判定
> （默认约 20% 引用）。必须**同时**把 `random_enabled` 关掉，才是真正的一律不引用。

**场景三：只对少数群生效**

```toml
[group]
enabled = true
whitelist = ["123456789"]     # 只对这些群生效（填群号）
min_message_gap = 3
```

**场景四：间隔不足不引用，满足间隔则随机**

```toml
[group]
enabled = true
no_quote_below_gap = 3   # 间隔低于 3 条一律不引用（硬性，不参与随机）
min_message_gap = 0      # 不启用间隔阈值，其余交给随机判定
```

和场景一对照着看：场景一用的是**软**条件（满足间隔才引用，未满足仍可能引用），
这里用的是**硬**否决（间隔不足即不引用），两者可以叠加。

**场景五：群聊与私聊各用一套权重**

```toml
[group]
random_enabled = true
quote_weight = 0.5           # 群聊：50% 引用、50% 不引用
no_quote_weight = 0.5
at_weight = 0.1              # 群里偶尔 @ 人

[private]
random_enabled = true
quote_weight = 0.2           # 私聊：20% 引用
no_quote_weight = 0.8
at_weight = 0.0              # 私聊不 @（默认就是 0）
```

两节各自独立，改群聊不会影响私聊——**没有"全局权重"需要先覆盖**。权重是相对值，
上面就是 50 : 50 与 20 : 80；把 `at_weight` 填 `0` 即退回两态。
想让私聊一律不引用的话，把 `[private]` 换成场景二即可。

打开 `advanced.verbose_log = true` 后，每次判定会额外输出一行：


末尾括号内即判定原因，常见取值：

| 判定原因 | 含义 |
| --- | --- |
| `命中引用关键词「…」（备注名）` | 被回复的消息命中了某条 `action = "引用"` 的条目 |
| `命中不引用关键词「…」（备注名）` | 被回复的消息命中了某条 `action = "不引用"` 的条目；括号里是命中条目的备注名（没填就是「第 N 条」） |
| `该会话类型未启用会话控制｜随机→…` | 本节「启用会话控制」已关闭 |
| `命中排除名单` | 发言者在「排除名单」中 |
| `不在生效名单｜随机→…` | 配置了「生效名单」且发言者不在其中 |
| `未启用间隔条件｜随机→…` | 两个间隔阈值均为 0 |
| `目标消息不在本次上下文中｜随机→…` | 被回复的消息已不在本次上下文里 |
| `间隔低于硬阈值，不引用（间隔 N 条 < M）` | 被「低于该间隔不引用」否决 |
| `间隔条件未命中（间隔 N 条 < M）｜随机→…` | 未达到「引用间隔阈值」，交给随机判定 |
| `间隔条件命中（间隔 N 条 ≥ M）` | 达到「引用间隔阈值」，一律引用 |

`｜随机→…` 表示该结论来自随机判定，末尾的「引用 / 不引用 / @对方」是抽取结果；
若配置了 `at_weight` 但麦麦未开启富回复，还会追加 `（@ 未叠加：麦麦未开富回复）`。

## 常见问题

**Q：配置面板里「关键词」那一栏看不懂，到底要不要填？**
A：**不用填**，它只是给个别消息开小灶的例外清单，**默认就是空的**，留空完全不影响使用。
面板上点「添加」就能新增一条，每条填四件事：**关键词**、**命中后**（引用 / 不引用）、
**生效会话**（不限 / 仅群聊 / 仅私聊）、以及可选的**限定群号 / QQ 号**。
每个字段旁都有备注，照着填即可。匹配的是**被回复的那条消息**的正文，子串包含、忽略大小写。

**Q：为什么我设了「引用间隔阈值」，模型却还是经常引用？**
A：「引用间隔阈值」（`min_message_gap`）是**软**条件——间隔达到它才算满足，不满足就交给
随机判定（默认约 20% 引用）。若你希望"间隔不够就绝不引用"，改用「低于该间隔不引用」
（`no_quote_below_gap`）：低于它一律不引用，且不参与随机判定。

**Q：我把「启用会话控制」关掉了，为什么这类会话还会引用？**
A：关掉它只是"跳过本节的名单与间隔条件"，**不是**"完全不干预"。这类会话会直接改用随机判定
（默认约 20% 引用）；若同时关掉了「启用随机判定」，才会改用该会话类型的「固定引用行为」。
想彻底不引用，两者一起设为不引用（见场景二）。

**Q：@ 功能怎么不生效？**
A：`@` 需要麦麦的 `experimental.enable_rich_reply = true`。未开启时插件会自动退化为普通回复，
并在 `/引用关键词` 与判定原因里提示。这不是插件的问题，是麦麦把 `attach_at` 归入了
富回复参数组，同一个开关控制三个参数。

**Q：装了插件后模型看不到附图能力了，这是 bug 吗？**
A：不是，是本插件的设计。`strip_rich_attachments = true`（默认）会在请求发出前把
`attach_pic` / `attach_emoji` 从 `reply` 的参数里移除。想恢复就把该项设为 `false`。

**Q：会破坏麦麦的分段回复或文本润色吗？**
A：不会。插件改的只有 `reply` 调用的 `set_quote` / `attach_at` 两个参数，回复文本原样不动；
`@` 组件由麦麦在自己发送时拼接，所以分段与润色都不受影响。

**Q：日志里写着「已改写 N 个 reply 参数」，但实际回复的引用行为没变化？**
A：先确认插件已加载（日志有 `智能引用已加载：…`），且声明的能力 `send.text` /
`chat.get_all_streams` 已获授权（缺声明会被宿主拒绝，日志出现 `E_CAPABILITY_DENIED`）。
还要注意 `N` 是**字段级改动数**（改 `set_quote`、写/清 `attach_at`、移除附图参数各算 1），
不是「改了 N 条回复」。另外，如果这条回复的间隔未达到「引用间隔阈值」，判定会交给**随机判定**
——此时「这条没引用」本身就是预期行为，不是改写失效。

## 已知限制

1. **消息间隔只在当前上下文窗口内可算**。上下文是麦麦筛选过的，被回复的消息如果过旧、
   已不在本次发给模型的历史里，则无法计算 → 落到随机判定，不会猜测。
2. **间隔是上下文内的相对条数差**，不是 QQ 群里的绝对条数差。对「要不要引用」这个决策而言，
   相对间隔正是最合适的信号——模型看到的也是同一份上下文。
3. 插件仅在 Maisaka 决策链上生效，**不影响回复文本的生成风格**。
4. 消息顺序表与消息正文表都按 `session_id` 只保留最近一次的值（每次整体替换，不做累加），
   **仅存内存**，麦麦重启即清空；重新填充之前发生的判定会走"目标消息不在上下文中"分支。

## 依赖说明

核心功能**仅通过麦麦 SDK 公开 API 实现**，只有一处为了读取「富回复开关」而
**直接读取了麦麦内部实现**：

| 用途 | 依赖路径 | 说明 |
|------|----------|------|
| 会话类型 / 对端 ID | **SDK 能力** `chat.get_all_streams` | 主路径。返回主进程的会话表快照（含 `is_group_session` / `group_id` / `user_id`），结果缓存 60 秒。这是唯一能跨进程拿到权威会话信息的方式。 |
| 会话类型 / 对端 ID（兜底） | `src.chat.message_receive.chat_manager` | 仅当上面的能力调用失败时才尝试。插件 Runner 是独立子进程，此路径通常拿不到数据，命中与否不影响正确性。 |
| 富回复开关 | `src.config.config.global_config.experimental.enable_rich_reply` | SDK 未提供读取该开关的公开接口；导入失败时保守视为「未开启」（即不使用 `@` 形态）。 |

最后一处属于**绕过 SDK 的强耦合**，在麦麦大版本更新（内部路径变动）时可能失效；
失效后的表现是 `@` 形态自动退化为普通回复，不影响引用判定本身。
为此已将 `host_application.max_version` 收窄至当前已验证的小版本范围，
更高版本需重新验证后再放宽。

需要声明的能力（写在 `_manifest.json` 的 `capabilities` 里，否则宿主会拒绝调用）：

- `send.text` — 发送命令回复
- `chat.get_all_streams` — 读取会话表，判定会话类型与对端 ID
